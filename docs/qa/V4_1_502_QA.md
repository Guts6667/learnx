## Navigateur : deux suites complémentaires

La suite de développement conserve les trois catalogues internes `/design/*`,
qui sont intentionnellement absents du build livré. Elle a produit **76 tests
réussis, 36 ignorés intentionnellement et 0 échec** sur Desktop Chrome,
Pixel 5, tablette Chromium et iPhone 13/WebKit. Les quatre tests du catalogue
Totem ont également été rejoués après correction du champ React contrôlé :
**4 / 4 réussis**, sans avertissement React.

Les 36 cellules ignorées ne masquent pas des parcours : cinq spécifications
exécutent elles-mêmes leurs matrices de largeur sur desktop et ignorent leurs
répétitions dans les trois autres projets. Répartition : primitives UI 12,
journal Recherche 9, recherche publique 9, auth publique 3 et landing 3.

Une seconde configuration exécute le **bundle de production exact** :

```bash
pnpm test:e2e:production
```

Résultat final : **72 réussis, 24 ignorés intentionnellement et 0 échec** sur
les quatre projets. Les catalogues de design sont exclus parce qu'ils ne sont
pas des routes produit. Le service worker est bloqué dans cette seule suite
afin que les interceptions API de chaque contexte restent isolées ; son
manifest, son build, ses états d'installation/offline/update et son contrôleur
sont couverts par les tests PWA dédiés.

Un premier essai exploratoire du build avait mélangé les catalogues
development-only et le service worker avec les mocks, produisant des faux
échecs sous WebKit. Le protocole a été séparé avant le verdict final, sans
modifier une route, un contrat ou un comportement produit.

## Accessibilité et responsive

Les parcours ciblés contrôlent automatiquement :

- 320, 390, 720, 1440 et 1920 px, plus texte à 200 % ;
- absence de débordement horizontal et reflow des contenus techniques ;
- clavier, focus visible et restitution du focus après dialogue ;
- cibles tactiles, libellés accessibles et ordre de navigation ;
- `prefers-reduced-motion` ;
- absence de violation Axe `serious` ou `critical` pour WCAG 2.0 A/AA et
  WCAG 2.1 A/AA sur les parcours couverts.

La preuve automatisée ne remplace pas un lecteur d'écran natif, le zoom du
navigateur ni une installation PWA sur téléphone. Ces trois contrôles sont
conservés dans la recette propriétaire V4.1-504.
